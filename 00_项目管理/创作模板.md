# 创作模板

按当前任务取用，不必填写所有字段。文档归属和修改过程见[协作与版本管理](协作与版本管理.md)。

<a id="template-general"></a>
## 一条设定

- 名称、所属主文档。
- 当前定义：用一段话说清它是什么。
- 必要边界：它不能解释什么，何时失效。
- 来源与状态：明确输入、现行整理、候选或未定；有原文则附定位。
- 剧情用途：改变了谁的选择，或解释了哪种生活。

<a id="template-rule"></a>
<a id="template-existence"></a>
<a id="template-power"></a>
## 规则或能力的补充字段

分清规则与存在。只在确有需要时补写作用对象、媒介、条件、代价和一个失败例子。新增后天规则还需说明适用范围与持续成立的依据，避免为个例改写整个世界。

<a id="template-story-ledgers"></a>
## 一个角色或场景

- 角色想得到什么，正在保护谁或什么。
- 他知道什么、误解什么，这与作者已知事实有何不同。
- 他作出什么选择，谁承担后果。
- 场景结束后，关系或处境发生了什么变化。
- 新增公共事实回写哪里；伏笔采用或撤销了哪一条。

不要求每个角色预先拥有悲惨身世、秘密血统、重大过错或牺牲结局。

## 一次 AI 任务与交接

任务写明：本次目标、允许修改的位置、必须阅读的主条目、需要保留的方向。交付写明：完成了什么、采用了什么、留下什么未定，以及直接受影响的文档。

审校优先找实际矛盾、重复定义、缺失因果和被误写成定案的候选。不要因资料尚有空白就自行发明整个体系。

## 一次重要变更

记录“原内容 → 当前内容、改动原因、来源、影响位置”即可。精简和撤回同样是有效修改，不必为被删除的假设再造一个世界内解释。
