## 来源优先与内容状态

创作者最新明确指示优先于旧输入中的冲突部分；不冲突的旧输入继续有效。其后依次为有明确批准记录的内容、本轮推荐工作稿。不能只按文件编号、日期或措辞肯定程度决定事实优先级。

| 标记 | 含义与使用边界 |
| --- | --- |
| 创作者明确 | 来自直接输入或明确选择；仍需区分方向与尚未展开的细节 |
| 推荐工作稿 | 用于继续推演的当前方案，可被修改；不等于已获批准 |
| 未定／留白 | 尚无选择，或明确延后；需注明允许探索的范围 |
| 历史归档 | 记录旧版本与未选素材；默认不进入新任务的依据 |

具体条目的流转状态为：候选 → 评审中 → 已批准 → 已发布；失效内容另标已替代或已弃用。当前还没有完整正式正典，工作任务须绑定当前文件与相关未决项，不能假称在使用一个已发布正典版本。

陈述层次独立记录：作者层事实、世界内说法、创作留白。一个已收录的传说，并不证明传说的内容属于作者层真相。真相是否已定、哪些人可以看到，也与工作状态分开。混合条目逐条标注，不用单个可信度百分比替代来源。

创作者输入提要与原图保存在资料区，逐字文字以原始聊天为准。现行解释放回对应主文档；改动输入记录的排版或提要，不得伪造新的创作者决定。

## 人类职责与 AI 工作角色

| 人类职责 | 需要作出的决定 | 对应 AI 工作角色 | AI 的交付边界 |
| --- | --- | --- | --- |
| IP 发起人或创意负责人 | 定位、核心主题、重要方向及底层规则的重大变化 | 方案整理助手 | 提出选项、差异和后果，不代替选择 |
| 总编或世界观负责人 | 正典、跨模块冲突、时代和力量边界、版本发布 | 总体规划助手 | 拆解任务、整理依赖、汇总决策，不自行宣布定稿 |
| 模块负责人 | 模块内设定质量、与相邻模块的一致性 | 模块创作助手 | 在指定范围内提出候选条目及影响说明 |
| 设定编辑或资料管理员 | 条目身份、引用、状态、纪年和版本可追溯 | 资料整理助手 | 提取已知事实、生成检索包、报告缺失资料 |
| 审校人员 | 一致性、因果、可叙事性及原创表达 | 一致性审校助手、故事压力测试助手 | 提供有证据的发现，不直接改写其他模块 |
| 作品负责人 | 作品目标、人物、情节和具体媒介表达 | 故事与改编助手 | 提交情节、场景及新增设定清单 |

早期建议设置三个职责席位：创意与总编、世界与资料、故事与制作。可以由少于三人承担，但高影响设定尽量由起草者之外的人复核。没有额外人手时，分开进行起草与审校，并明确二者不是独立人员审查。

## 内容模块与交接

每个模块需要一名人类负责人。人员较少时可以兼任，但每项设定仍应只有一个明确的责任归属。模块数量是内容分类，不代表必须配置同样数量的员工或 AI。

| 编号与模块 | 核心问题 | 首轮交付 | 主要依赖与交接 |
| --- | --- | --- | --- |
| M00 创作宪章与总编 | 项目讲什么、遵守什么、哪些内容定稿 | 宪章、术语规范、决策记录、发布清单 | 向全部模块提供共同约束 |
| M01 宇宙与底层规则 | 世界结构、生命死亡、时空、可知边界是什么 | 最小规则集、禁区、例外程序 | 为 M02、M03、M04 提供边界 |
| M02 力量与修习 | 力量从何而来，如何取得、学习、支付代价和反制 | 力量规则表、时代能力表、使用场景 | 与 M05、M07、M08 联合检查社会影响 |
| M03 神话与神圣存在 | 神如何行动，创世事件留下什么 | 神话事件、神圣存在、遗产关系 | 依赖 M01；向 M04、M05、M09 输出遗产 |
| M04 地理与生态 | 哪里能生活，资源如何流动，环境如何变化 | 分层地图、气候水系、资源与异常区域 | 与 M03、M05 协商起源及栖居条件 |
| M05 生命与智慧族群 | 生命形态如何影响感知、生计和社会可能性 | 生命谱系、族群卡、生态和寿命条件 | 不替 M06 决定所有文化，不替 M07 决定所有国家 |
| M06 文明与文化 | 群体如何生活、记忆、命名、祭祀和表达价值 | 文明卡、文化变体、命名规则、信仰解释 | 依赖环境和生命条件，与 M09 关联演化 |
| M07 国家与组织 | 谁掌握权力，如何分配、继承和制约 | 国家、地方共同体、宗教及学派组织卡 | 接收 M06、M08、M09；约束人物活动 |
| M08 生计与技术 | 食物、能源、劳动、交通、通信和交易如何运作 | 生产与流通模型、技术边界、日常场景 | 检查 M02 是否改变资源稀缺性和社会结构 |
| M09 历史与纪年 | 事件何时发生、为何发生、留下什么 | 总年表、地方年表、纪年换算、因果链 | 汇合多模块；不得独立改写其规则 |
| M10 人物与故事 | 谁想得到什么，受到谁或什么阻碍 | 人物关系、故事企划、场景、情节与新事实清单 | 绑定时代、地区和已发布设定 |
| M11 视觉与声音 | 世界如何被辨认、不同文明如何表现 | 形制、材料、服饰、建筑、图案、音色与语言节奏 | 从环境、生产和文化推导；区分概念稿与定稿 |
| M12 媒介与产品改编 | 不同作品提供什么体验、怎样共享世界 | 改编规则、体验目标、版本绑定、作品新增设定 | 与 M10、M11 协作，差异回交 M00 |

模块是创作职责，文档是共享事实的存放位置；多个模块可以共用一个主条目。未明确分派时，负责人填写“未分派”，不把建议岗位当成已到岗成员。

## 创作与合并流程

**提出需求 → 取得范围内资料 → 起草候选 → 检查依赖与叙事 → 人类裁决 → 合并并发布 → 更新受影响作品。**

| 步骤 | 输入 | 交付 | 完成条件 |
| --- | --- | --- | --- |
| 1 定义任务 | 作品需求或模块缺口 | 有范围、负责人和验收条件的任务书 | 哪些可以新增、哪些不可改变已经明确 |
| 2 整理资料 | 目标时代、地区、对象、正典版本 | 必要原文、相关条目、限制和未决问题 | 关键依赖齐全；缺失项明确标出 |
| 3 生成候选 | 任务书和资料包 | 少量有差异的方案、候选条目、依赖和影响说明 | 既有事实与新增提案分开 |
| 4 审校 | 候选文本和引用来源 | 按严重程度排序的发现、引文、修改建议 | 引用可定位，不能只给“设定不错”的评价 |
| 5 决策 | 候选、审校和受影响模块意见 | 通过、退回或选择方案，以及决策理由 | 对应人类负责人明确批准 |
| 6 合并 | 获批条目和决策记录 | 修订后的条目、引用更新、变更清单 | 主条目、依赖和目录一致 |
| 7 发布 | 一组通过检查的条目 | 正典版本快照与发布说明 | 使用者可以准确引用该版本 |
| 8 作品回写 | 完成的故事或改编 | 新增事实、世界状态变化和待确认内容 | 新事实经过同等评审后再进入正典 |

正典建立后，“已批准”表示内容获准进入下一次发布；一般创作任务以“已发布”版本为默认依据。确需使用提前批准的内容时，在任务书中列出条目修订号和批准记录，避免不同任务使用不同的隐含版本。

任务的完成以验收通过为准，不以生成字数或提出多少新概念为准。

文档重组、错字修订等已授权维护直接执行；涉及未获批准的世界设定选择时，记录为候选并交相应创作者裁决，不把常规维护变成反复确认流程。

## AI 资料包与检索范围

默认读取项目总览、相关主文档、直接依赖和有关待决项。范围为 `00_项目管理`、`01_世界设定`、`02_世界历史`；需要核对创作者原意时读取 `资料`。`归档` 默认排除，仅在明确比较旧方案时打开。

任务资料包应包含使用版本、目标时代和地区、必要规则原文、允许新增的范围、禁止决定的事项，以及实际取得的来源清单。决定机制的关键条目必须读原文，不能仅用聊天摘要或搜索命中句。

检索不到资料只表示没有取得依据。原图箭头与最新澄清冲突时，先记录差异，按最新明确指示处理，不把图像更早的画法当成更高权威。输入缺失与本来不存在要分别判断。

## 并行任务与共享依赖

依赖未定时，可以并行探索候选方案；依赖定稿后，才适合并行生产能够合并的内容。

| 情况 | 工作方式 |
| --- | --- |
| 同一地区的不同节庆，已共享历法、宗教和经济条件 | 可并行起草，分别持有条目，最后检查重复与日程 |
| 相邻国家共用一条河流 | 先确认河流和水权的共同事实，再分别设计国家 |
| 新增长距离传送能力 | 先审查力量、交通、战争和经济影响，再开展依赖该能力的内容 |
| 两个作者同时需要修改同一英雄的死亡事件 | 由主条目负责人合并任务，不允许各自提交互斥定稿 |
| 地理暂未确认，故事需要一处渡口 | 可使用“待定渡口”占位或局部假设，禁止扩展为已确定的大陆水系 |

任务开始时记录输入版本和负责条目。合并前再次检查这些依赖是否变化；若已经变化，只重新检查受影响内容，不盲目重做全部世界。

模块负责人拥有维护责任，不拥有单方面修改共享底层规则的权限。跨模块变更由总编协调受影响负责人；作者之间不通过正文互相覆盖。

## 审校与严重程度

| 类别 | 要检查的具体问题 |
| --- | --- |
| 时代和规则 | 人物是否使用了本时代禁止的能力？条件性奇迹是否被写成常规技能？ |
| 地理与生态 | 路程、交通、水系、食物与资源是否支持事件发生？ |
| 年表与寿命 | 日期顺序、年龄、在位时间、迁徙时间是否相容？模糊日期是否仍可共存？ |
| 社会因果 | 治疗、通信、延寿、移动和生产能力会不会改变已有制度？这种影响是否被解释？ |
| 族群和文明 | 是否把族群、文化、政权混写？差异是否有生活后果与内部变化？ |
| 神与主角 | 神为何不直接处理问题？主角的例外能否被复制？故事是否因此失去阻力？ |
| 叙事 | 冲突是否支持不同诉求？人物选择是否改变结果？读者是否必须先读百科？ |
| 来源与表达 | 新概念是否只是换名复制？创作参考与改造是否记录？引用是否支持对应断言？ |

严重程度建议分三级：

- **阻断项**：违反已发布底层规则、形成互斥世界事实、使用未获准的重大例外、导致核心事件无法发生。解决前不发布。
- **需修订项**：社会后果缺失、动机薄弱、信息不足、命名或来源混淆。应修订；若有意留白，需要负责人记录其边界和理由。
- **优化项**：表达、节奏、辨识度和可选的扩展建议。由作品负责人按目标决定。

每个发现必须说明“涉及什么断言、依据在哪、为何冲突、影响哪些内容、可以怎样改”。没有引用支持的审校意见应标为疑问或创作判断。

可用规则检查器检查必填项、编号重复、断链、明确日期顺序和状态误用。AI 适合发现可能的逻辑问题，但不能证明全文无矛盾；主题质量、感染力和原创程度仍需人类判断。

规则自查判例随其主条目维护：一般规则见[规则与存在](../01_世界设定/规则与存在.md#ont-07)，灵魂判例见[生命与神圣存在](../01_世界设定/生命与神圣存在.md)，神干预判例见[补天法则](../01_世界设定/补天法则.md)。不再另抄一份内容相同的审校规则库。

<a id="change-flow"></a>
## 变更等级与版本发布

| 变更类型 | 示例 | 建议批准方式 |
| --- | --- | --- |
| 文字修订 | 错字、格式、没有歧义的别名补录 | 条目负责人确认，记录修订 |
| 局部扩展 | 在已有城市中增加一项不影响公共规则的习俗 | 模块负责人及资料检查 |
| 跨模块变化 | 改变河道、国家边界、人物生死、重要资源来源 | 总编和受影响模块负责人共同确认 |
| 核心变化 | 调整世界结构、时代能力边界、复活条件或神的干预条件 | 发起人或创意负责人和总编决策，并提供迁移方案 |

正典采用“世界主版本、扩展版本、修订版本”区分变化。例如主版本变化代表不能完全兼容旧作品的核心调整；扩展版本增加兼容内容；修订版本修正不改变事实的文字。具体编号形式由团队统一。

项目当前文档版本见总览；文档整理版本与世界正典版本分别记录，整理目录不等于批准设定。

每次发布保存条目清单和修订号，不只保存一个发布日期。正在制作的作品继续使用所绑定的快照；新正典发布不自动改变其人物和规则。作品升级版本时要重新检查受影响部分。

### 追溯修改的处理

发现既有矛盾时，先确认是世界内不同说法，还是作者层事实冲突。前者可以共存，后者需要处理：

1. 保留旧事实，修改尚未发布的新稿。
2. 在既有规则允许范围内补充限定，且说明为什么过去未被涉及。
3. 正式修订旧事实，发布变更原因、影响清单与迁移说明。
4. 为确有必要的改编建立明确分支，不让两个互斥版本混用。

不得用“史书都是假的”“某神抹除了所有人的记忆”作为通用修补方式。这样的事件若成立，也必须满足世界规则并留下可追踪后果。

一次修改按下列顺序完成：找到主条目 → 修改其唯一正文 → 更新相关待决项状态 → 按引用检查受影响文档与作品 → 检查链接、编号、状态及必要场景 → 记录本次变更。只有影响到内容的引用方才调整，不为更新日期而重写全部文件。

创建快照时记录文件清单与内容校验值；旧版不与现行正文平铺。作品绑定的快照保持不变，升级时做影响检查。

### 现有主文档的影响检查路线

链接既可以表示来源，也可以只是阅读导航；出现互链不等于两项设定互为生成前提。判断影响时从改变的具体断言出发，至少检查下表范围。

| 改动入口 | 必查内容 | 常见失配 |
| --- | --- | --- |
| [规则与存在](../01_世界设定/规则与存在.md) | [生命的参与规则](../01_世界设定/生命与神圣存在.md)、[补天的上位约束](../01_世界设定/补天法则.md)、[创世生成表和关系图](../02_世界历史/创世与时代总表.md#history-creation) | 先驱生命倒用后来规则，或后天法则越过本源 |
| [生命与神圣存在](../01_世界设定/生命与神圣存在.md) | [补天的神格判据](../01_世界设定/补天法则.md)、[女娲与诸神的诞生](../02_世界历史/神话与传说事件.md)、[后世修习和轮回提案](决策与待办.md#d10) | 成神条件与剧情不符，身份连续性被另一篇改写 |
| [补天法则](../01_世界设定/补天法则.md) | [补天事件、千年战争与神农支持方式](../02_世界历史/神话与传说事件.md)、[时代能力变化](../02_世界历史/创世与时代总表.md#history-eras) | 禁限已改而神仍以旧方式行动 |
| [创世与时代总表](../02_世界历史/创世与时代总表.md) | [事件前提、人物称号与寿命](../02_世界历史/神话与传说事件.md)、[规则适用时间](../01_世界设定/规则与存在.md)、[相关任务依赖](决策与待办.md) | 神的诞生早于所需条件，或同一王朝重复建立 |
| [神话与传说事件](../02_世界历史/神话与传说事件.md) | [总表中对应节点](../02_世界历史/创世与时代总表.md)，以及后续建立的地方遗产及人物条目 | 改写事件后留下一套旧因果链 |
| [创作模板](创作模板.md)或[协作制度](协作与版本管理.md) | [当前任务书与条目元数据](创作模板.md)、[发布清单要求](协作与版本管理.md#change-flow) | 多套状态名或必填字段并存 |

结构检查通过后，仍应审查改变是否取消人物困境或生活后果；不能把链接有效等同于故事逻辑无误。

## 运行节奏与工具发展

每批只处理一组相关设定和能够检验它的场景。以阻断冲突是否解决、引用是否完整、返工是否减少、人物能否作出有效选择衡量质量，不以生成字数或名词数量衡量。

初期使用目录、模板、人工审校与归档。检索成为负担后再增加检索工具；多作品并行后再增加依赖图、任务队列和自动检查。AI 草稿先进入候选，正式发布保留明确的人类决定。具体平台与运行周期尚未选定。
